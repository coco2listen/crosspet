# Claude 分端额度和独立服装（本地续修）

用户澄清截图问题是两端额度相同，并要求两个 Claude 的服装独立。本轮仍只本地实现，不推送、不创建或更新 PR。

## 根因与改动

旧 mod 的两个额度入口都写 `claude-quota.json`，两个 Claude 窗口又都读该文件；最后写入者覆盖两端显示。现保留 legacy 文件供单宠 / 旧三宠使用，另按已证明的 client 发布两份原子文件。unknown 不写成已知端；空额度清本端，目录创建或发布失败不打断 Claude hook。网页校验 schema/family/source/client；缺失或不匹配时标为待更新，不以旧共享数值填充。其他家族合并额度保留两条有端身份的 Claude 行。

Claude 衣服使用各宠 `outfitV1`；首次复制当前共享选择，明确空字符串表示原版。换衣服只重载当前 Claude，设置页显示本端服装；大小、出现方式、额度开关等仍共享。独立衣服例外仅限 Claude，GPT/DSH 保留原共享行为。旧 skins 和旧域均保留。

## 安装时尚待真实客户端加载

安装后检查两端真实独立额度文件均尚未产生：运行中的旧 Claude mod 不会热更新。新版 App 将显示“终端额度待更新 / 桌面额度待更新”，不再把旧共享额度冒充两端数据。应在当前任务结束后，让两端加载新版 CrossPet mod，再由真实 usage / session.measure 更新。此次没有声明两端真实额度数字已核验通过。

本轮未重跑 Python、真实鼠标拖动、全屏、Windows、Intel 或长时间稳定性测试。


## 后续收尾：真实数据已产生

再次检查时，两份真实文件都已由新 mod 产生，schema/family/source/client 均匹配：终端 5 小时剩余 91%、本周 94%；桌面 85%、本周 18%。这部分是实际客户端元数据，不是合成 15% / 65% 测试值。无需再为本次核验重启客户端。

对正在运行的已安装 CrossPet 做只读窗口检查，只有一个主进程。终端窗口可访问性内容显示“终端 · Offline”及 91% / 94%，与本端文件一致；宿主已退出时该宠 alpha=0，未强制唤出。桌面宠 alpha=1、服装为睡衣；其窗口贴在左边且处于收起状态，截图中额度栏隐藏，因此本次未把桌面实际可见数字标为直接核验通过。桌面真实来源文件与隔离原生渲染验证分别如上记录。

用户已将服装调整为终端原版（outfitV1=""）、桌面睡衣（claude-pajamas）；本次收尾保留该选择，没有恢复上次安装时的演示服装。桌面窗口截图仅包含 CrossPet 自身，未截取其他应用内容。
